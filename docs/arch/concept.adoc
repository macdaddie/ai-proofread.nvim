== Executive Summary

*AI Proofread* (`ai-proofread.nvim`) is a
lightweight Neovim plugin providing AI-assisted proofreading
of prose and markup documents.

Its primary responsibilities are:

* Spelling.
* Grammar.
* Punctuation.
* Configurable long-sentence detection and splitting.
* User-triggered application of validated corrections.
* User-triggered dismissal of unwanted recommendations.

The plugin uses a selected local model through native Apple
`fm` or Ollama and presents findings through Neovim's native
quickfix list.

The initial Ollama model is `gemma4:12b-it-qat`, subject to
further proofreading-specific evaluation.

All application-specific logic shall be implemented in Lua.
No custom Swift application, cloud API, external account
or additional application service is required.

The plugin complements conventional language tools,
including Harper LSP, without attempting to replace
their continuous diagnostics.

== Problem Statement

Traditional spelling and grammar tools provide useful
mechanical checks, but some errors depend on context and
are difficult to detect reliably.

General-purpose AI assistants can help, but introduce
unnecessary interaction and may suggest changes outside
the author's intended scope.

AI Proofread addresses this problem through a
focused, on-demand proofreading workflow integrated
with Neovim.

== Vision

Provide a local, unobtrusive proofreader that identifies
spelling, grammar, punctuation and configured long
sentences without
interfering with the author's writing process.

The author invokes a review, examines the findings and
decides whether to apply corrections individually or
all at once.

The reviewer advises; the author retains control.

== Objectives

The project shall:

[cols="1,1",frame=none, grid=none]
|===
a|
. Integrate natively with Neovim using Lua.
. Use selectable local inference through Apple `fm` or
  Ollama.
. Operate without external network connectivity.
. Support text and markup document formats.
. Restrict operation to configured filetypes.
. Analyse unsaved buffer contents.
. Support complete-buffer and visual-selection reviews.
. Use British English by default.
a|[start=9]
. Detect spelling, grammar and punctuation errors.
. Detect sentences above a configured word limit and offer
  meaning-preserving splits.
. Return structured findings with replacement text.
. Present findings through native quickfix.
. Preserve accurate source locations.
. Apply a selected validated correction on request.
. Apply all validated corrections on request.
. Ignore a selected recommendation on request.
. Execute asynchronously.
. Never modify document contents without an explicit
  application command.
. Require minimal installation and configuration.
|===

== Scope

=== In Scope

The implementation supports:

[cols="1,1",frame=none,grid=none]
|===
a|
* British English spelling checks.
* Context-sensitive grammatical checks.
* Punctuation checks.
* Configurable long-sentence checks.
* Code-detected long-sentence candidates with validated
  model rewrites.
* User-triggered application of one validated correction.
* User-triggered application of all validated corrections.
* Filetype-specific protection of non-prose content.
a|
* Document segmentation for model context limits.
* Exact-source finding validation.
* Quickfix navigation.
* Review cancellation.
* Model and service availability checks.
|===

=== Correction Application

Correction application is always initiated by the author.

The current quickfix finding may be applied individually,
or all remaining validated findings from the latest review
may be applied in one operation.
The current finding may instead be ignored without changing
the buffer.

Before changing the buffer, the plugin shall verify that
each target range still contains the exact source slice
captured during validation.

Bulk application shall reject overlapping corrections,
preflight every target before making any change and create
one undo step.

Failure of any bulk preflight check shall leave the buffer
unchanged.

A successfully applied correction shall be removed from the
quickfix list.
Individual application shall select the next outstanding
finding, and successful bulk application shall leave the
list empty.
Ignoring shall remove the current finding, select the next
one and exclude the ignored finding from bulk application.
Failed corrections shall remain visible.

=== Out of Scope

The initial release shall not include:

[cols="1,1",frame=none, grid=none]
|===
a|
* General stylistic editing.
* Document-wide rewriting.
* Unrestricted sentence readability or restructuring beyond
  configured long-sentence splitting.
* General clarity or concision analysis.
* Ambiguity analysis as an independent review category.
* Redundancy and repetition analysis as independent checks.
* Logical consistency checking.
* Word-choice analysis beyond grammatical correctness.
* Document usage or terminology consistency checking.
* Project-wide terminology-policy enforcement.
a|
* Fact-checking.
* Edits triggered without an explicit author command.
* Cloud inference.
* A conversational interface.
* Continuous inference while typing.
* A custom Language Server Protocol implementation.
* Retrieval-augmented generation.
* Document rendering or publishing.
|===

Additional editorial capabilities require an explicit
scope decision and are not implied by the use of an LLM.

Model names are configuration values rather than

The implementation supports native Apple `fm` and local
Ollama as explicitly selected backends.

Native `fm` is an optional backend for immediate trial on
supported Macs; it trades proofreading quality for zero
model downloads and faster startup.

== User Experience

=== Implementation Status

The runnable plugin implements module loading,
configuration, backend selection, command registration,
complete-buffer and visual-selection reviews, source
mapping, protected markup, response decoding, optional
Ollama preload, individual and bulk correction application,
recommendation ignoring, cancellation, stale results,
partial failure and hard limits.

=== Normal Workflow

. Open a supported document in Neovim.
. Execute `:AIProofread`.
. The plugin captures the current buffer contents.
. The document is divided into reviewable sections.
. Each section is submitted to the selected local model.
. Structured findings are validated and consolidated.
. The quickfix list is populated and opened.
. The author navigates through the findings.
. The author applies the current correction, applies all
  validated corrections or ignores the recommendations.

=== Commands

[cols="2,3",options="header"]
|===
|Command |Purpose

|`:AIProofread`
|Review the current buffer.

|`:AIProofreadSelection`
|Review the most recent characterwise or linewise selection.

|`:AIProofreadCancel`
|Cancel the active review.

|`:AIProofreadHealth`
|Check the selected backend, configuration and model status.

|`:AIProofreadApply`
|Apply the correction at the current quickfix entry.

|`:AIProofreadApplyAll`
|Apply all remaining corrections from the latest review.

|`:AIProofreadIgnore`
|Ignore the current recommendation and select the next one.
|===

These commands constitute the implemented command API.

=== Findings

Each finding is either a localised spelling, grammar or
punctuation correction, or a whole long-sentence rewrite,
with an exact source quotation and suggested replacement.

All findings use quickfix severity `W`.

=== Example Quickfix Output

[source,text]
----
article.adoc|24 col 18| W: Grammar: "it's" -> "its"
article.adoc|83 col 12| W: Spelling: "organize" -> "organise"
----

Severity is derived by the plugin, never from
the model response.

`E` is not used, because the model supplies no
calibrated confidence signal from which a higher
severity could be derived.

Severity shall not be presented as a statistically
calibrated model confidence score.

== Filetype Configuration

The plugin shall use Neovim's filetype mechanism to
determine eligibility.

Example:

[source,lua]
----
require("ai-proofread").setup({
  language = "en-GB",
  backend = "ollama",

  ollama = {
    url = "http://127.0.0.1:11434",
    model = "gemma4:12b-it-qat",
    timeout_ms = 120000,
    temperature = 0,
    preload = false,
    -- keep_alive = "1h",
  },

  fm = {
    command = "fm",
    model = "system",
    timeout_ms = 30000,
  },

  filetypes = {
    asciidoc = true,
    markdown = true,
    text = true,
  },

  checks = {
    spelling = true,
    grammar = true,
    punctuation = true,
  },

  review = {
    chunk_size = 2500,
    hard_limit = 12000,
  },

  quickfix = {
    auto_open = true,
  },

  keymaps = {
    review = "<leader>ar",
    review_selection = "<leader>ar",
    apply = "<leader>aa",
    apply_all = "<leader>aA",
    ignore = "<leader>ai",
  },
})
----

The filetype list is an allowlist.

Unsupported filetypes shall not be reviewed by default.

=== Format Awareness

Filetype-specific adapters shall identify prose and
protect non-prose content.

Examples include:

* AsciiDoc attributes and source blocks.
* Markdown fenced code and frontmatter.
* URLs, references and document directives.

The plugin shall not assume that all text in a buffer
is natural-language prose.

Typst and RTF are deferred until dedicated parsers can
produce reviewable prose with reversible source-byte maps.

== Review Principles

=== Author-Controlled Edits

Review never changes the buffer.

The plugin modifies text only after the author invokes an
individual or bulk application command.

Every edit remains undoable through Neovim's normal undo
history.

=== British English

British English shall be the default language convention.

Valid British spelling, punctuation and grammatical
constructions shall not be flagged merely because they
differ from American English.

British collective-noun agreement shall be treated
according to context rather than rejected categorically.

=== Authorial Voice

The model shall preserve the author's meaning, tone,
terminology and intended style.

=== Local Privacy

Document content shall be sent only to the native `fm`
process or configured local Ollama endpoint.

No automatic cloud fallback shall be permitted.

Document contents shall not be written to diagnostic
logs by default.

=== Complementary Language Tools

AI Proofread complements Harper LSP and similar
language tools.

Harper provides continuous language diagnostics.

AI Proofread provides deliberate, context-sensitive
proofreading, localised spelling, grammar and punctuation
corrections, and configured long-sentence rewrites.

The plugin shall not require Harper to be installed.

=== Manual Invocation

Review shall occur only following an explicit command.

No model inference shall be triggered automatically
by ordinary editing, buffer changes or saves.

== Conceptual Workflow

[plantuml,ai-proofread-concept,svg]
----
@startuml
skinparam monochrome true
skinparam shadowing false

:Open document;

if (Configured filetype?) then (Yes)
  :Invoke review;
  :Capture buffer snapshot;
  :Protect markup and segment prose;
  :Invoke selected local model per chunk;
  :Validate structured findings per chunk;
  :Append quickfix entries as chunks finish;
  :Navigate findings while review continues;

  if (Correction appropriate?) then (Yes)
    :Apply one or all corrections;
    :Verify exact source slice;

  endif

  :Report unsupported filetype;
endif

@enduml
----

== Non-Functional Requirements

=== Performance

* Neovim shall remain responsive during review.
* Model execution shall be asynchronous.
* Large documents shall be segmented.
* Findings shall be published as each chunk completes.
* Review cancellation shall be supported.
* Excessive concurrent model requests shall be avoided.
* A general review shall use one inference pass per chunk
  unless evaluation justifies additional passes.

=== Reliability

* Invalid model output shall not crash Neovim.
* Invalid source locations shall be rejected.
* Results shall be checked against the buffer snapshot.
* Model unavailability shall produce actionable errors.
* Partial review failures shall be reported.
* Rejected findings shall be counted and reported.
* No findings shall be fabricated.

=== Security

* Ollama mode shall connect only to a configured loopback
  endpoint.
* Native mode shall invoke only the local `fm` command.
* Document text shall be treated as untrusted input.
* Model output shall never be executed as code.
* No automatic cloud fallback shall be permitted.
* No persistent plaintext temporary files shall be required.

=== Maintainability

* The implementation shall remain Lua-only.
* Neovim-native APIs shall be preferred.
* Each inference transport shall be isolated in its own
  module behind a shared controller contract.
* Filetype adapters shall be independently testable.
* Third-party runtime dependencies shall be minimised.
* Additional editorial categories shall not be introduced
  without an explicit scope decision.

== Success Criteria

The implemented proof of concept demonstrates:

[cols="1,1",frame=none, grid=none]
|===
a|
. The selected backend and model can be verified.
. A short document produces valid structured findings.
. British English spelling is handled correctly.
. Representative grammar errors are identified.
. Representative punctuation errors are identified.
. Correct British English produces acceptably few
  false-positive findings.
a|[start=7]
. A supported Neovim buffer can be reviewed.
. Unsaved changes are included in the review.
. Findings appear in the quickfix list before later
  chunks finish.
. Navigation reaches verified source locations.
. Protected markup is not reported as prose.
. Unsupported filetypes are rejected.
. A selected correction can be applied safely.
. All corrections can be applied atomically and undone
  as one operation.
. Stale or overlapping corrections are not applied.
. A characterwise or linewise visual selection can be
  reviewed with original-buffer coordinates.
. Suggestions that do not change the source text are
  rejected.
. Optional Ollama preload does not block editor startup.
. The workflow functions without external connectivity.
|===

The remaining release work is hardening and language-quality
evaluation.

== Model Evaluation

The initial model selection is provisional.

The existing local comparison demonstrates that
`gemma4:12b-it-qat` is a promising candidate for
structured language review.

However, the comparison used one passage and three
prompt variants, with substantial emphasis on editorial
capabilities outside the revised project scope.

The final selection shall use a proofreading-specific
corpus of approximately 40 passages.

[cols="1,1",frame=none,grid=none]
|===
a|
The corpus shall include:

* Spelling errors.
* Grammar errors.
* Punctuation errors.
* Correct British English.
* Clean passages containing no errors.
* AsciiDoc markup and protected regions.
* Repeated source phrases.
* Technical prose.
a|
Evaluation shall measure:

* Precision and false-positive rate.
* Recall by supported category.
* Correction quality.
* Exact-source quotation accuracy.
* Finding granularity.
* Markup protection.
* Review latency.
|===

Model fit and parameter count alone shall not determine
the selection.

== Future Enhancements

Potential later capabilities include:

* Project-specific terminology dictionaries.
* Optional inline diagnostics.
* Incremental review of changed sections.
* Review of multiple buffers.
* Configurable severity thresholds.

These are not requirements for the initial release.

General editorial analysis remains explicitly outside
the agreed scope unless separately authorised.
