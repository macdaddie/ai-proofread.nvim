== Architecture Overview

AI Proofread is a Lua-based Neovim plugin providing
on-demand British English proofreading through native
Apple `fm` or local Ollama.

The release supports four checks:

* Spelling.
* Grammar.
* Punctuation.
* Long sentences above a configurable word limit.

The solution comprises three logical layers:

. Neovim integration and presentation.
. Document preparation, validation and orchestration.
. Selected local inference through `fm` or Ollama.

All application-specific logic resides in Lua.

No custom Swift executable, Python runtime, custom HTTP
server or additional persistent application service
is required.

=== Implementation Status

The implemented plugin provides:

* A stable `setup()`, `review()`, `cancel()`, `health()`,
  `review_selection()`, `apply()`, `apply_all()` and
  `ignore()` public API.
* Review, cancellation, health, individual-application,
  bulk-application and ignore commands.
* Asynchronous, sequential requests to the selected backend.
* Selectable native Apple `fm` and local Ollama adapters.
* Optional asynchronous Ollama model preload during setup.
* A packaged three-category JSON Schema.
* Plain text, Markdown and AsciiDoc adapters.
* Exact and whitespace-collapsed quotation validation.
* Rejection of no-op, stale, ambiguous and overlapping
  findings.
* Characterwise and linewise visual-selection review.
* Cancellation, stale-buffer rejection and partial-failure
  handling.
* Source-verified quickfix start and end positions.
* User-triggered individual and bulk correction application
  plus individual recommendation ignoring.
* Headless tests and real `fm` and Ollama review paths.

Typst and RTF remain deferred until dedicated parsers can
provide reversible source mappings.

Ollama and native `fm` supply local inference; exactly one
backend is active for a review.

== Architectural Principles

* Prioritise proofreading over general editorial analysis.
* Minimise dependencies and operational complexity.
* Separate probabilistic inference from deterministic validation.
* Preserve document content and source coordinates.
* Modify source only after an explicit application command.
* Use British English by default.
* Protect markup and technical content.
* Use explicit filetype activation.
* Avoid blocking the editor.
* Keep model selection configurable.
* Fail safely and visibly.
* Do not introduce abstractions without a clear requirement.

== Component Design

=== Configuration Module

[cols="1,1",frame=none,grid=none]
|===
a|
Responsible for:

* Default settings.
* User configuration validation.
* Filetype allow lists.
* Filetype-specific overrides.
a|
* The three supported proofreading checks.
* British English conventions.
* Backend selection between `fm` and Ollama.
* Ollama endpoint and model selection.
* Native command, model and timeout selection.
* Optional Ollama preload and per-request keep-alive
  settings.
* Timeout and chunk-size settings.
* Quickfix presentation preferences.
|===

=== Review Controller

[cols="1,1",frame=none, grid=none]
|===
a|
Responsible for:

* Review lifecycle.
* Buffer snapshot creation.
* Request identification.
* Chunk scheduling.
a|
* Result aggregation.
* Cancellation.
* Stale-result detection.
* Error reporting.
* Progress reporting.
|===

=== Progress Reporter

Responsible for reporting review state before quickfix has a
finding.

The reporter shall use a Neovim progress message with a stable
message id, so updates replace one message instead of filling
the message history.

The message shall show the backend, chunk position, current
phase and elapsed time. It shall refresh on a timer so that a
long inference request remains visibly active.

The reporter shall mark the final state as success, failure or
cancellation. It shall also expose a formatted status string
for statusline integration through `require("ai-proofread").status()`.

=== Filetype Adapters

Responsible for identifying reviewable prose and
protecting structural markup.

Implemented adapters:

[cols="1,3",options="header"]
|===
|Adapter |Responsibility

|Plain text
|Paragraph segmentation.

|AsciiDoc
|Protect source blocks, attributes, directives,
references and structural markup.

|Markdown
|Protect fenced code, frontmatter and markup.

|===

Typst and RTF are deferred. Each requires a parser that can
produce reviewable prose and a reversible source-byte map.

Adapters shall retain mappings to original buffer
coordinates.

=== Markup Protection

Non-prose content shall be excluded from inference
or represented by protected sentinels.

Protected content includes:

* Source and literal blocks.
* URLs.
* Document attributes.
* Cross-references and directives.
* Inline code.
* Format-specific structural syntax.

The implementation shall preserve a mapping between
reviewable text and original source positions.

Length-preserving masking may be used where practical.

Otherwise, explicit transformed-to-original offset
maps are required.

The implemented offset map is a per-chunk array indexed by
review-text byte position. Each value is the corresponding
absolute byte position in the captured buffer text.

Inline masking shall preserve byte length, padded with
a repeated filler character, so that the column delta
within a line remains zero.

Line breaks remain unchanged during masking so line and
column calculations remain stable.

A model finding shall never be accepted solely because
its quotation matches a sentinel.

=== Chunk Management

Responsible for:

* Context-budget enforcement.
* Paragraph-aware segmentation.
* Source-line preservation.
* Chunk identification.
* Sentence-boundary preservation.
* Hard-limit reporting.
* Result consolidation by the controller.

Chunk boundaries shall prefer paragraphs and sections.

Long paragraphs may be divided at sentence boundaries.

Sentences above the configured hard limit are not submitted
to the selected backend. They are counted as unreviewable
sections and make the review incomplete.

=== Prompt Module

Responsible for constructing model instructions.

Instructions shall specify:

* British English by default.
* Spelling, grammar, punctuation and configured long
  sentences only.
* No unrelated editorial analysis.
* Preservation of meaning and authorial voice.
* Respect for technical terminology.
* Protection of markup and source code.
* Exact quotations from the supplied text.
* One independent finding per error.
* A `type` of `correction` for local errors.
* A `type` of `rewrite` for complete long sentences.
* No response to instructions embedded in reviewed text.

The default review shall use a single general
proofreading prompt per chunk.

Long-sentence candidates shall be detected in Lua before
inference.
The general prompt shall describe the category without
enumerating candidates, and the validator shall reject any
rewrite outside that set.

A focused retry prompt shall be used only for a rejected
candidate whose first rewrite was a no-op or an invalid
bounded split.
It shall quote exactly one candidate between explicit markers.
Retries shall be bounded per chunk and shall use a response
schema limited to one long-sentence rewrite.

=== Ollama Adapter

Responsible for:

* Validating the configured endpoint.
* Checking model availability.
* Constructing API requests.
* Sending document content as JSON.
* Enforcing structured output.
* Handling asynchronous responses.
* Enforcing timeouts.
* Handling cancellation.
* Reporting transport and inference failures.

The adapter shall not invoke a shell.

It shall use Neovim's native asynchronous facilities.

The implementation uses `vim.system()` to invoke `curl`
without shell interpolation or command-line document text.

A future native HTTP implementation may replace this
transport without changing the review controller.

=== Apple fm Adapter

Responsible for invoking `fm respond` asynchronously with
the system model, greedy generation and the packaged
structured-output schema.

The adapter shall invoke the command asynchronously with
`vim.system()`, supply document text through standard input
and enforce the configured timeout.

The command shall use the packaged
`fm_response_schema.json` schema for general reviews and
`fm_rewrite_response_schema.json` for focused rewrite retries.
It shall use a non-streaming response and greedy generation.

The response is a direct JSON findings document, unlike the
Ollama transport, which nests a JSON string inside a
`response` field.

The adapter shall decode that document before the common
validator processes its findings and shall report process or
decoding failures as transport errors.

=== Finding Validator

Responsible for:

* JSON decoding.
* Schema validation.
* Category and type validation.
* Type and category coupling.
* Severity derivation.
* Exact source-text matching.
* Protected-region rejection.
* Line and column verification.
* Duplicate removal.
* Rejection of ambiguous source locations.
* Rejection of suggestions that do not change the source.
* Tracking rejected findings by reason.

=== Quickfix Presenter

Responsible for converting validated findings into
Neovim quickfix entries.

It shall use native Neovim APIs and introduce no
additional UI dependency.

=== Correction Applier

Responsible for:

* Applying the current quickfix correction.
* Applying all remaining corrections from the latest review.
* Ignoring the current recommendation.
* Tracking validated ranges with buffer extmarks.
* Verifying the exact validated source slice immediately
  before each edit.
* Rejecting stale, missing or overlapping corrections.
* Applying bulk corrections as one undoable operation.

The applier shall never use unvalidated model output.

Bulk application shall complete its full preflight before
changing the buffer. If any correction fails preflight,
the buffer shall remain unchanged.

== Configuration Design

The public API is:

[source,lua]
----
require("ai-proofread").setup({
  language = "en-GB",
  backend = "ollama",

  ollama = {
    url = "http://127.0.0.1:11434",
    model = "gemma4:12b-it-qat",
    temperature = 0,
    timeout_ms = 120000,
    preload = false,
    -- keep_alive = "1h",
  },

  fm = {
    command = "fm",
    model = "system",
    timeout_ms = 30000,
    chunk_size = 800,
  },

  filetypes = {
    asciidoc = true,
    markdown = true,
    text = true,
  },

  checks = {
    spelling = true,
    grammar = true,
    punctuation = true,
    long_sentence = true,
  },

  long_sentence = {
    max_words = 30,
  },

  review = {
    chunk_size = 2500,
    hard_limit = 12000,
    max_concurrent = 1,  -- Reserved; no runtime effect.
  },

  quickfix = {
    auto_open = true,
    height_ratio = 1 / 3,
    keep_focus_on_select = true,
  },

  keymaps = {
    review = "<leader>ar",
    review_selection = "<leader>ar",
    apply = "<leader>aa",
    apply_all = "<leader>aA",
    ignore = "<leader>ai",
  },
})
----

The chunk size and hard limit are byte budgets, not model
token counts.

The `fm` backend uses `fm.chunk_size`; Ollama uses
`review.chunk_size`. The `fm` default is smaller because
empirical testing showed that 2,500-byte structured requests
can exceed the effective on-device context and take roughly a
minute before failing. An 800-byte budget returned structured
findings in single-digit seconds in the same test.

The configured model is provisional pending
proofreading-specific evaluation.

== Inference Backend Integration

=== Prerequisites

The plugin requires Neovim 0.12 or later and either:

* The native Apple `fm` command with the system model.
* A running local Ollama service, an installed compatible
  model and access to the configured loopback endpoint.

The health command validates only the selected backend.

For Ollama it checks endpoint access and configured model
availability through `/api/tags`.

For native `fm` it checks that the configured command is
executable.

=== Ollama Service Discovery

Illustrative checks:

[source,bash]
----
command -v ollama
ollama --version
ollama list
curl -sS http://127.0.0.1:11434/api/tags
----

The plugin shall report whether the configured model
is available locally.

It shall not automatically download models.

=== Ollama API Invocation

The Ollama adapter uses the `/api/generate` endpoint.

Requests shall include:

* Model identifier.
* Review instructions.
* Document content.
* JSON Schema output constraint.
* Non-streaming response selection.
* Temperature zero.
* A configured `keep_alive` value when supplied.

When preload is enabled, `setup()` shall start an
asynchronous `/api/generate` request containing the model,
`stream: false` and no prompt.
If `keep_alive` is omitted, Ollama's configured
`OLLAMA_KEEP_ALIVE` value governs model residency.

The preload attempt shall be bounded by
`ollama.preload_timeout_ms` and shall never block startup or a
later review.

A failed preload shall be reported at debug level and shall not
be treated as a backend failure.

Transport failures shall be classified so that a timeout, a
refused connection and a protocol error produce distinct
messages.

The health command shall report the models currently held by
Ollama so that a busy or queued service is visible.

Conceptual request:

[source,json]
----
{
  "model": "gemma4:12b-it-qat",
  "stream": false,
  "think": false,
  "options": {
    "temperature": 0
  },
  "system": "Proofread British English prose.",
  "prompt": "Text to review.",
  "format": {
    "type": "object",
    "properties": {
      "findings": {
        "type": "array",
        "items": {
          "type": "object",
          "properties": {
            "type": {"type": "string"},
            "original": {"type": "string"},
            "suggestion": {"type": "string"},
            "category": {"type": "string"},
            "message": {"type": "string"}
          },
          "required": [
            "type",
            "original",
            "suggestion",
            "category",
            "message"
          ],
          "additionalProperties": false
        }
      }
    },
    "required": ["findings"],
    "additionalProperties": false
  }
}
----

The production schema shall restrict `category` to
`spelling`, `grammar`, `punctuation` or `long_sentence`.

Local findings use type `correction`.
Long-sentence findings use type `rewrite`.

The response body returned by Ollama contains a
`response` field holding the model-generated JSON.

The adapter shall decode the transport response first,
then decode and validate the nested findings document.

A nested value that decodes to a further string shall
be decoded once more.

An empty or undecodable `response` field shall fail the
chunk and shall never be treated as an absence of
findings.

Models that support a thinking channel require
`think` to be set to `false`, otherwise the `response`
field can be empty.

=== Ollama Process Execution

The Ollama transport invokes `curl` asynchronously using
`vim.system()`.

Illustrative Lua:

[source,lua]
----
local payload = vim.json.encode(request)

local process = vim.system({
  "curl",
  "--silent",
  "--show-error",
  "--fail-with-body",
  "--max-time", "120",
  "--header", "Content-Type: application/json",
  "--data-binary", "@-",
  "http://127.0.0.1:11434/api/generate",
}, {
  text = true,
  stdin = payload,
  timeout = 120000,
}, function(result)
  vim.schedule(function()
    handle_result(result)
  end)
end)
----

This illustrates the transport mechanism only.

The production implementation shall validate the
endpoint, process status, HTTP response and JSON.

No shell interpolation shall be used.

Document contents shall not be placed in command-line
arguments.

=== Native fm Invocation

The native adapter invokes the configured `fm` command with:

[source,text]
----
fm respond --model system --no-stream --greedy \
  --schema fm_response_schema.json \
  --instructions "<system prompt>"
----

The review prompt is supplied through standard input.

Document contents are never placed in command-line
arguments.

The adapter shall validate the process exit status and
decode the direct JSON response.

A non-zero exit or invalid response shall fail the chunk and
shall never be treated as an absence of findings.

The shared validator shall process the decoded findings in
the same way as Ollama findings.

=== Schema Handling

The plugin shall package a general JSON Schema and a narrow
rewrite-retry JSON Schema.

For Ollama, the general schema permits all supported finding
categories, while the retry schema permits exactly one
`rewrite` finding in the `long_sentence` category.

For `fm`, equivalent packaged schema files serve the same two
purposes.

Schema enforcement improves response consistency but
does not establish that findings are correct.

All model output shall undergo deterministic validation.

== Review Data Contract

=== Internal Finding Representation

The canonical internal representation is:

[source,json]
----
{
  "line": 24,
  "column": 18,
  "end_line": 24,
  "end_column": 21,
  "severity": "warning",
  "type": "correction",
  "category": "grammar",
  "message": "Incorrect possessive form.",
  "original": "it's",
  "source_text": "it's",
  "suggestion": "its"
}
----

These are original-buffer coordinates after validation.
The end position is exclusive.

The model shall not be trusted to calculate source
line numbers or byte offsets.

`line`, `column`, `end_line`, `end_column`, `source_text`
and `severity` are derived by the plugin.

The model supplies only `type`, `category`, `original`,
`suggestion` and `message`.

Published findings also retain an internal review
identifier, extmark identifier and applied state. These
editor-state values are not supplied by the model and are
not part of the quickfix text.

`source_text` is the exact original-buffer slice at the
validated range. It may differ from the model's `original`
only when the bounded whitespace fallback resolves a
hard-wrapped quotation.

The contract is fixed by ADR-021 and revised by ADR-036.

=== Supported Categories

[cols="1,3",options="header"]
|===
|Category |Purpose

|`spelling`
|Misspellings and incorrect spelling variants.

|`grammar`
|Grammatical errors.

|`punctuation`
|Incorrect or missing punctuation.

|`long_sentence`
|A complete sentence containing more than the configured
word limit.

|===

Other categories shall be rejected.

Spelling, grammar and punctuation use type `correction`.
Long sentences use type `rewrite`.

=== Model Response

Example correction:

[source,json]
----
{
  "findings": [
    {
      "type": "correction",
      "original": "recieved",
      "suggestion": "received",
      "category": "spelling",
      "message": "Incorrect spelling."
    }
  ]
}
----

Example long-sentence rewrite:

[source,json]
----
{
  "findings": [
    {
      "type": "rewrite",
      "original": "The complete source sentence ...",
      "suggestion": "First shorter sentence. Second shorter sentence.",
      "category": "long_sentence",
      "message": "Split this sentence to improve readability."
    }
  ]
}
----

=== Source-Location Strategy

The model shall identify an exact offending text span.

The validator shall locate that span within the
reviewable text of the chunk that produced it.

A finding shall be rejected when:

* The quotation is not an exact match.
* The quotation occurs more than once.
* The quotation overlaps protected content.
* The category is unsupported.
* `type` and `category` are inconsistently paired.
* The suggestion is identical to the quoted or source text.
* A `long_sentence` quotation does not exceed the configured
  word limit.
* The category is disabled in configuration.
* A long-sentence quotation is not an exact code-detected
  candidate.
* A long-sentence suggestion does not contain at least two
  sentences within the configured limit.
* A field contains a disallowed control character or exceeds
  its size limit.
* The finding belongs to a stale review.

Where an exact match fails, one whitespace-collapsing
pass is permitted, and that pass shall also produce
exactly one match.

Repeated quotations are therefore rejected as
ambiguous rather than resolved by preference.

It shall never invent a location.

Rejected findings shall be counted by reason and
reported.

The matching rules and reason codes are fixed by
ADR-021.

=== Finding Granularity

Each independent spelling, grammar or punctuation
error should be reported separately.

A long-sentence rewrite shall quote its complete source
sentence.
It shall preserve meaning, factual detail and authorial
voice while splitting that sentence.

When a validated long-sentence rewrite contains local
corrections, the rewrite shall supersede those corrections
to prevent overlapping quickfix entries.

The benchmark shall assess finding granularity
independently of defect detection.

=== Unicode Handling

Neovim quickfix columns use byte-oriented positions.

Lua shall calculate UTF-8 byte offsets from the
original buffer text.

Character positions supplied by the model shall not
be assumed to be valid Neovim column positions.

== Review Lifecycle

[plantuml,ai-proofread-sequence,svg]
----

participant Neovim
participant "Lua Controller" as Lua
participant "Inference Adapter" as Adapter
participant "Selected Local Model" as Model
participant "Correction Applier" as Applier

Author -> Neovim : :AIProofread

Lua -> Lua : Check filetype

loop Each chunk
  Lua -> Lua : Check changedtick
  Lua -> Adapter : Submit review request
  Adapter -> Model : JSON inference request
  Model --> Adapter : Structured response
  Adapter --> Lua : Parsed findings
  Lua -> Lua : Validate and locate findings
  Lua -> Applier : Add validated corrections
  Lua -> Neovim : Append quickfix entries

  alt Explicit apply during review
    Author -> Neovim : Apply current or all
    Neovim -> Applier : Verified findings
    Applier -> Neovim : One undoable edit
    Applier --> Lua : Byte and line deltas
    Lua -> Lua : Rebase pending chunks
    Lua -> Neovim : Refresh quickfix positions
  else Ignore during review
    Author -> Neovim : Ignore current
    Neovim -> Applier : Mark ignored
    Neovim -> Neovim : Remove quickfix entry
  end

  Lua -> Neovim : Report stale review

  Lua -> Neovim : Remove published entries

== Buffer Snapshot Management

The controller shall record:

* Buffer number.
* Buffer name.
* Filetype.
* Buffer changedtick.
* Source lines.
* Review identifier.

Before publishing each chunk, the controller shall verify
that the original buffer still exists and that its
changedtick has not changed.

An external change shall discard the review.

An explicit apply from the plugin's own correction state
shall instead rebase pending chunks and advance the baseline
changedtick, as recorded in ADR-035.

== Document Segmentation

=== Context Limits

The selected model has a finite context window.

The plugin shall reserve capacity for:

* Review instructions.
* Schema-related overhead.
* Document text.
* Generated findings.

The model's advertised maximum context shall not
automatically be used as the operating context.

The practical budget shall be determined experimentally.

=== Segmentation Rules

. Prefer section and paragraph boundaries.
. Avoid splitting sentences where possible.
. Preserve source line mappings.
. Exclude or mask protected markup and code.
. Keep chunks within the configured context budget.
. Avoid unnecessary overlapping review regions.
. Report unreviewable sections explicitly.

A single sentence that exceeds the chunk budget shall
be reviewed alone, without neighbouring text.

If it still exceeds the hard context limit, it shall be
divided at a safe prose boundary or reported as an
unreviewable section.

=== Scheduling

The implementation processes one chunk at a time.

For `fm`, chunks are prepared with `fm.chunk_size` so each
structured request stays within the effective on-device
context. Ollama uses `review.chunk_size`.

Concurrency may be introduced later if benchmarks
demonstrate a benefit.

`review.max_concurrent` is reserved for that decision and
has no runtime effect.

The default shall be one general proofreading pass
per chunk.

A bounded focused rewrite retry may follow the general pass
for that chunk.

The controller shall publish valid findings before starting
any retries for that chunk.

It shall publish findings after each chunk completes or fails
and shall start the next chunk only after retries finish.

`chunks_done` shall count only chunks that have been processed,
so it equals `chunks_total` when the review finishes.

== Quickfix Integration

The plugin shall use Neovim's native quickfix list.

The controller shall create the list when the first batch is
published, and shall ensure it exists when the review finishes.
It shall append each chunk's sorted findings to that list.

Illustrative implementation:

[source,lua]
----
vim.fn.setqflist({}, "r", {
  title = "AI Proofread", -- <1>
  items = {},
})

local id = vim.fn.getqflist({ id = 0 }).id -- <2>

vim.fn.setqflist({}, "a", { -- <3>
  id = id,
  items = findings,
})
----
<1> The title is fixed. Progress belongs in quickfix context.
<2> The id is captured once so every append targets the same list.
<3> Each validated chunk is appended, so entries removed by apply or
ignore are never restored from an accumulator.

The production counterparts are
`lua/ai-proofread/quickfix.lua` and
`lua/ai-proofread/controller.lua`.

The list title shall remain `AI Proofread`.

Progress and completion shall be reported through quickfix
context.

Each finding shall include:

* Buffer number.
* Line number.
* Verified start and end byte columns.
* Severity type.
* Finding type, category and explanation.
* Suggested correction.
* An immutable finding identifier in quickfix `user_data`.

Findings shall be sorted by source location.

When `quickfix.auto_open` is enabled, the window shall open
on the first published finding.

The source window and cursor shall be restored afterwards.

The auto-opened window height shall be at least the
configured ratio of the Neovim screen height.

By default, pressing Enter in the AI Proofread quickfix
window shall move the source window to the selected finding
without moving focus out of quickfix.

Quickfix window discovery shall exclude location-list
windows.
Source preview shall use the window that started the review
and shall not replace an arbitrary split.

Corrections shall be applied only through explicit
individual or bulk application commands.

=== Correction Application

Each published finding shall retain its verified source
range and an extmark that follows intervening edits.

Individual application shall:

. Resolve its `user_data` identifier to a validated finding.
. Read the current text at the tracked range.
. Require an exact match with the finding's `source_text`.
. Replace that range with `suggestion`.
. Mark the finding as applied.
. Remove its quickfix entry and select the next entry.

Bulk application shall:

. Select all unapplied findings from the latest review, or
  only those in an explicit quickfix command range.
. Resolve and verify every tracked source range.
. Reject duplicate or overlapping ranges.
. Abort without edits if any preflight check fails.
. Apply edits from the end of the buffer towards the start.
. Join the changes into one Neovim undo step.
. Remove all applied entries from quickfix.

An explicit range on `:AIProofreadApply` shall refer only
to rows in the active AI Proofread quickfix window.
The command shall reject source-buffer and location-list
ranges without changing the document.
Selected rows shall resolve by immutable finding identifier
and belong to the same active review.
Normal invocation without a range shall still apply only
the current quickfix entry.

Applied findings shall not be applied again.
Failed or stale findings shall remain in quickfix.
Undo shall not recreate removed quickfix entries; a new
review is required to repopulate the list.

Ignoring shall mark the current finding as ignored, remove
its extmark and quickfix entry, and select the next
outstanding finding.
Ignored findings shall not be included in bulk application.

== Error Handling

=== Correction Application Failure

Individual application shall fail without changing the
buffer if its finding cannot be resolved, has already been
applied or no longer matches its exact source slice.

Bulk application shall report the failed preflight reason
and leave the buffer unchanged.

=== Service or Model Unavailable

The health command distinguishes:

* Ollama service unavailable.
* Configured Ollama model not installed.
* Native `fm` command unavailable or not executable.

Review execution separately reports transport failure,
invalid responses and request timeout as failed chunks.

=== Invalid Output

The plugin shall reject:

* Malformed transport JSON.
* Malformed model-generated JSON.
* Empty or undecodable `response` fields.
* Unexpected schema structures.
* Unrecognised `type` values.
* Unsupported categories.
* Inconsistently paired `type` and `category` values.
* Unverifiable source locations.
* Quotations that occur more than once.
* Findings overlapping protected content.
* Results from superseded reviews.
* Responses over one MiB.
* Responses containing more than 200 findings.
* Oversized finding fields.
* Failed or undecodable focused rewrite retries.

=== Partial Failure

If one or more chunks fail, the review shall be
marked incomplete.

Successfully validated findings may still be displayed,
provided the incomplete status is visible.

=== Cancellation

The controller shall retain the active request handle.

Cancellation shall terminate the request where possible.

The controller shall prevent cancelled or superseded
requests from publishing results.

Cancellation shall also remove quickfix entries and extmarks
belonging to the cancelled review.

== Security and Privacy

=== Local Execution

Each backend shall execute locally.

Ollama mode shall connect only to the configured loopback
endpoint.

Configuration shall accept only `localhost`, `127.0.0.1` or
`[::1]` as the Ollama endpoint host.

Native mode shall invoke only the configured local `fm`
command.

Remote inference and automatic cloud fallback are
outside scope.

=== Transport

The adapters shall:

* Use only the configured local transport.
* Avoid shell interpolation.
* Send document content through standard input or the
  request body.
* Validate process status, transport status and responses.
* Never execute generated text.
* Avoid persisting document contents.

=== Prompt Injection

Reviewed documents are untrusted data.

Text within a document must not override the
proofreading instructions or request unrelated actions.

Model responses shall be treated as untrusted data.

=== Logging

Debug logs shall contain operational metadata only
by default.

Document contents and full model responses shall not
be persisted without explicit user opt-in.
