1. INTRODUCTION                          *ai-proofread-introduction*

AI Proofread checks prose with Apple's native `fm` command or a local
Ollama model and places source-verified findings in the quickfix list.

Supported filetypes are `text`, `markdown` and `asciidoc`.

Supported categories are spelling, grammar, punctuation and long_sentence.
Long-sentence rewrites split sentences above a configurable word limit
while preserving meaning, detail and authorial voice. Other editorial
categories and unrestricted sentence rewriting are out of scope.
Candidates are detected in Lua before inference. Only exact candidates
whose resulting sentences meet the configured limit are accepted.

2. SETUP                                        *ai-proofread-setup*

>lua
  require("ai-proofread").setup({
    backend = "ollama",
    ollama = {
      url = "http://127.0.0.1:11434",
      model = "gemma4:12b-it-qat",
      preload = true,
      -- preload_timeout_ms = 120000,
      -- keep_alive = "1h",
    },
  })
<

Set backend = "fm" to use Apple's native on-device Foundation Model
instead of Ollama. This requires no downloaded Ollama model but provides
lower proofreading quality. Both backends use the same source validation.

The plugin never downloads models. Run |:AIProofreadHealth| to check the
selected backend and model before reviewing.

3. COMMANDS                                  *ai-proofread-commands*

                                                *:AIProofread*
:AIProofread
        Review the current buffer and replace the AI Proofread quickfix
        list. Each validated chunk is published as soon as it completes.

                                      *:AIProofreadSelection*
:AIProofreadSelection
        Review the most recent characterwise or linewise visual selection.
        In visual mode, the default <leader>ar mapping invokes this command.
        Blockwise selections are not supported.

                                          *:AIProofreadCancel*
:AIProofreadCancel
        Cancel the active review for the current buffer.

                                           *:AIProofreadHealth*
:AIProofreadHealth
        Check whether the selected backend and model are available.

                                            *:AIProofreadApply*
:AIProofreadApply
        Apply the correction at the current quickfix entry after verifying
        that its source text has not changed. This also works while a
        review is active. Pending chunks are rebased and the review
        continues. A successful correction is removed from quickfix and
        the next outstanding entry is selected.
        To apply several entries, select their quickfix rows with Visual
        Line mode (V), then type :AIProofreadApply. Neovim supplies the
        selected range. Only those entries are applied, in one undo step,
        after the same stale and overlap checks as :AIProofreadApplyAll.
        Ranges are accepted only from the AI Proofread quickfix window,
        not from source-buffer lines.

                                         *:AIProofreadApplyAll*
:AIProofreadApplyAll
        Apply all remaining published corrections from the latest review.
        This also works during an active review. The command aborts before
        editing if any range is stale or overlaps another correction. A
        successful bulk application is one undo step and clears the applied
        entries from quickfix. Failed corrections remain.

                                           *:AIProofreadIgnore*
:AIProofreadIgnore
        Ignore the current quickfix recommendation without changing the
        buffer. This also works during an active review; the review simply
        continues. The entry is removed, the next recommendation is
        selected, and the ignored correction is excluded from bulk
        application.

A suggestion that does not differ from the quoted source text is rejected
and never reaches quickfix.

Long sentences are detected in Lua before inference. A rejected rewrite
may receive one focused retry with a narrow response schema. Valid
findings are published before retries start. Retries are capped per
chunk, and the next chunk starts only after retries finish.

Starting a review updates a single progress message. It shows the backend,
current chunk, phase and elapsed time, and it refreshes every two seconds.
The message reports success, partial failure or cancellation when the review
ends. This makes a slow fm request visibly active.

                                             *ai-proofread-status()*
require("ai-proofread").status()                      *ai-proofread-status*
        Return a statusline-ready string for the current buffer. The string
        contains the backend, current chunk, phase and elapsed time. It
        returns an empty string when no review is active.

Findings are appended to the AI Proofread quickfix list as each chunk is
validated. Entries removed by apply or ignore are not restored by later
chunks. The quickfix title remains "AI Proofread". The quickfix context
reports complete, chunks_done, chunks_total, review_id, rejected,
failed_chunks and unreviewable_sections. chunks_done counts processed
chunks and equals chunks_total when the review finishes. The rejected
count includes rejected rewrite retries. The complete field is false
while chunks remain and after a failed or unreviewable chunk.

When quickfix.auto_open is enabled, the quickfix window opens on the first
published finding at the configured height. The source window and cursor
are restored afterwards.

Pressing Enter on an AI Proofread quickfix entry moves the source window
to that location while focus remains in quickfix. Set
quickfix.keep_focus_on_select to false for Neovim's normal focus-changing
behaviour.

Any buffer change outside the plugin's apply operation makes the review
stale. The plugin stops the outstanding request and clears published
findings. |:AIProofreadCancel| clears the same artefacts for an active
review.

The former foundation-review Lua module and FoundationReview commands
remain available as deprecated compatibility aliases.

Undo does not restore removed quickfix entries. Run :AIProofread again to
create a new review.

=============================================================================
4. CONFIGURATION                        *ai-proofread-configuration*

backend~
        "ollama" (default) or "fm".

ollama~
        url           Loopback Ollama endpoint. The host must be localhost,
                      127.0.0.1 or [::1]. Default:
                      "http://127.0.0.1:11434".
        model         Ollama model identifier. Default:
                      "gemma4:12b-it-qat".
        temperature   Sampling temperature. Default: 0.
        timeout_ms    Request timeout. Default: 120000.
        preload       Load the model asynchronously during setup().
                      Default: false.
        preload_timeout_ms
                      Bound for the asynchronous preload attempt.
                      Default: 120000.
        keep_alive    Per-request model residency duration. When omitted,
                      Ollama uses OLLAMA_KEEP_ALIVE.

fm~
        command       Native command name or path. Default: "fm".
        model         Native model. Default: "system".
        timeout_ms    Request timeout. Default: 30000.
        chunk_size    Byte budget per fm review chunk. Default: 800.
                      This is smaller than review.chunk_size because the
                      on-device model has a smaller effective context.

filetypes~
        Allowlist for text, markdown and asciidoc. Unsupported filetypes
        are not reviewed by default.

checks~
        Enable spelling, grammar, punctuation and long_sentence
        independently. Other category names are rejected. Set a check to
        false to exclude it from the prompt and from validation. All four
        checks are enabled by default.

long_sentence~
        max_words     Largest accepted sentence length. A sentence must
                      exceed this number to produce a finding. Default: 30.
        Only code-detected sentences may be rewritten. A no-op or invalid
        split receives one focused retry. Retries are capped per chunk.

review~
        chunk_size    Byte budget per review chunk. Default: 2500.
        hard_limit    Byte budget for a single reviewable section.
                      Default: 12000.
        max_concurrent
                      Reserved for bounded concurrency. Default: 1.
                      It currently has no runtime effect.

quickfix~
        auto_open     Open the quickfix window on the first published
                      finding, then restore the source window. Default:
                      true.
        height_ratio  Minimum fraction of the Neovim screen used when
                      opening quickfix. Default: 1/3.
        keep_focus_on_select
                      Keep focus in quickfix when Enter previews a finding
                      in the source window. Default: true.

keymaps~
        review, review_selection, apply, apply_all and ignore accept a
        mapping string. Set a mapping to false or "" to disable it.

The configured model is provisional pending proofreading-specific
evaluation.

=============================================================================
5. BACKENDS AND PRIVACY                      *ai-proofread-backends*

Ollama is the default and provides better proofreading quality. The
native fm backend is faster to start but substantially less capable;
expect lower recall and more rejected findings. There is no automatic
fallback between backends. Both backends use general and rewrite-retry
schemas with the same source validation.

The fm backend uses fm.chunk_size instead of review.chunk_size. Its smaller
default keeps structured responses inside the effective on-device context.
Larger fm chunks can take much longer and may fail with a context-size error.

The first use of fm may require accepting Apple's terms through the fm
command.

Document text is sent only to the native fm process or the configured
local Ollama endpoint. No cloud fallback is implemented.

Ollama preload and keep-alive settings apply only to the Ollama backend.
The fm model is managed by macOS.

=============================================================================
6. TROUBLESHOOTING                    *ai-proofread-troubleshooting*

Run |:AIProofreadHealth| before reviewing. For Ollama it reports the
models currently held in memory.

The progress message confirms that a review is active before quickfix has
a finding. Use |:AIProofreadCancel| to stop a running review.

The quickfix title is always "AI Proofread". If context.complete is false
after the final chunk, inspect context.failed_chunks and
context.unreviewable_sections. Findings from successful chunks remain
available.

A preload request can time out while another model is loading or while
the GPU is saturated. Preload failures are harmless and appear only at
debug level. Increase ollama.preload_timeout_ms if the first load of a
large model is consistently slower than the default.

Ollama unloads idle models and queues requests when a model does not fit
in memory. By default it permits three models per GPU. Check the
effective server settings with:

>bash
  ps eww -p "$(pgrep -f 'ollama serve' | head -1)" \
    | tr ' ' '\n' | grep '^OLLAMA_'
  ollama ps
<

The ollama stop command cannot interrupt an active generation. If a
runner remains in Stopping..., restart the service only once other work
is idle.
