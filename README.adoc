
= AI Proofread for Neovim

AI Proofread is a Neovim plugin for on-demand British
English proofreading with a selected local backend: Apple's
native `fm` command or a local Ollama model.

It reviews prose without sending document contents to a cloud
service and publishes verified findings to Neovim's quickfix
list.

== Status

The plugin is under active development.

The current implementation supports plain text, Markdown and
AsciiDoc buffers. Typst and RTF require dedicated parsers and
are not yet supported.

The complete Neovim-to-backend-to-quickfix path has been
verified with both native `fm` and the default Ollama model.
The automated headless suite also verifies loading,
configuration, backend selection, source mapping, markup
masking, validation, cancellation, stale-result handling,
partial failure, hard-limit reporting, visual selection,
streaming publication and correction application.

== Checks

* Spelling.
* Grammar.
* Punctuation.
* Long sentences above a configurable word limit.

Long-sentence suggestions split the sentence while
preserving meaning, detail and authorial voice.
Candidate sentences are detected in Lua before inference.
Only rewrites for those exact candidates are accepted, and
each resulting sentence must meet the configured limit.
Other editorial categories and unrestricted sentence
rewriting are deliberately outside scope.

== Requirements

* Neovim 0.12 or later.
* macOS with the native `fm` command, or a local Ollama
  service with an installed structured-output model.
* `curl` in `PATH` when using Ollama.

The provisional default Ollama model is
`gemma4:12b-it-qat`.
The plugin never downloads models.

== Installation

=== vim.pack

[source,lua]
----
vim.pack.add({
  "https://github.com/macdaddie/ai-proofread.nvim",
})

require("ai-proofread").setup()
----

=== lazy.nvim and LazyVim

[source,lua]
----
{
  "macdaddie/ai-proofread.nvim",
  opts = {},
}
----

=== Native packages

[source,bash]
----
git clone https://github.com/macdaddie/ai-proofread.nvim \
  ~/.local/share/nvim/site/pack/vendor/start/ai-proofread.nvim
----

Then configure the plugin in `init.lua`:

[source,lua]
----
require("ai-proofread").setup()
----

== Configuration

[source,lua]
----
require("ai-proofread").setup({
  language = "en-GB",
  backend = "ollama",
  ollama = {
    url = "http://127.0.0.1:11434",
    model = "gemma4:12b-it-qat",
    timeout_ms = 120000,
    preload = true,
    -- preload_timeout_ms = 120000,
    -- keep_alive = "1h",
  },
  fm = {
    command = "fm",
    model = "system",
    timeout_ms = 30000,
    chunk_size = 800,
  },
  filetypes = {
    asciidoc = true,
    markdown = true,
    text = true,
  },
  checks = {
    spelling = true,
    grammar = true,
    punctuation = true,
    long_sentence = true,
  },
  long_sentence = {
    max_words = 30,
  },
  review = {
    chunk_size = 2500,
    hard_limit = 12000,
    max_concurrent = 1, -- Reserved; no runtime effect.
  },
  quickfix = {
    auto_open = true,
    height_ratio = 1 / 3,
    keep_focus_on_select = true,
  },
  keymaps = {
    review = "<leader>ar",
    review_selection = "<leader>ar",
    apply = "<leader>aa",
    apply_all = "<leader>aA",
    ignore = "<leader>ai",
  },
})
----

All four checks are enabled by default.
Set a check to `false` to exclude that category from the
prompt and from validation.
The filetype table is an allowlist.

`long_sentence.max_words` is the largest accepted sentence
length.
A sentence must exceed that number to produce a
`long_sentence` finding.

Long sentences are detected in Lua before inference.
Only those exact sentences may be rewritten.
If the first rewrite is a no-op or does not produce a valid
bounded split, the plugin makes one focused retry for that
sentence.
Retries are capped per chunk.

The `fm` backend uses `fm.chunk_size` instead of
`review.chunk_size`. The default of 800 bytes keeps structured
requests inside the smaller on-device context. Ollama
continues to use `review.chunk_size`.

`quickfix.height_ratio` controls the minimum height used when
the plugin opens quickfix.
With `quickfix.keep_focus_on_select = true`, pressing Enter
previews the selected finding in the source window while
focus remains in quickfix.

`review.max_concurrent` is reserved for a later bounded
concurrency decision and currently has no runtime effect.

== Inference Backends

`backend = "ollama"` uses the configured local Ollama model
and remains the default because it provides better
proofreading quality.

The Ollama URL must use `localhost`, `127.0.0.1` or `[::1]`.
Remote Ollama endpoints are rejected so reviewed text cannot
leave the local machine through this configuration.

`backend = "fm"` uses Apple's native on-device Foundation
Model:

[source,lua]
----
require("ai-proofread").setup({
  backend = "fm",
})
----

The `fm` backend needs no Ollama installation or model
download on a supported, up-to-date Mac.
It is faster to start but substantially less capable, so
expect lower recall and more rejected findings.
Both backends use general and rewrite-retry schemas with the
same deterministic source validation before findings reach
quickfix.

The first use of `fm` may require accepting Apple's terms
through the `fm` command.

== Commands

`AIProofread`::
Review the current buffer.

`AIProofreadSelection`::
Review the most recent characterwise or linewise visual
selection.

`AIProofreadCancel`::
Cancel the active review for the current buffer.

`AIProofreadHealth`::
Check whether the selected backend and model are available.

`AIProofreadApply`::
Apply the correction at the current quickfix entry.

`AIProofreadApplyAll`::
Apply all remaining corrections from the latest review.

`AIProofreadIgnore`::
Ignore the current quickfix recommendation.

The former `foundation-review` Lua module and
`FoundationReview*` commands remain as deprecated
compatibility aliases.

== Progress Indication

Starting a review updates a single Neovim progress message.
It shows the backend, current chunk, phase and elapsed time.
The message updates in place every two seconds, so a slow
`fm` request remains visibly active.

The same state is available for a statusline:

[source,lua]
----
require("ai-proofread").status()
----

It returns an empty string when no review is active.
Use `:AIProofreadCancel` if a running review is no longer
needed.

== Review and Apply Corrections

. Open a supported `text`, `markdown` or `asciidoc` buffer.
. Run `:AIProofread` or press `<leader>ar` in normal
  mode to review the complete buffer.
. To review only part of a buffer, select it characterwise
  or linewise and press `<leader>ar`.
  `:AIProofreadSelection` reviews the most recent visual
  selection.
. The progress message shows that the review is running.
. Findings appear in the AI Proofread quickfix list as each
  chunk completes.
. Navigate published findings with `:cnext`, `:cprevious` or
  the quickfix window while later chunks are still reviewed.
. Press Enter in quickfix to preview the selected source
  location without leaving the quickfix window.
. Apply the current quickfix correction with
  `:AIProofreadApply` or `<leader>aa`.
. Ignore the current recommendation with
  `:AIProofreadIgnore` or `<leader>ai`.
. Alternatively, apply every remaining published correction
  from that review with `:AIProofreadApplyAll` or
  `<leader>aA`.

The current correction is the entry selected in the
AI Proofread quickfix list.
The apply command can be invoked from either the quickfix
window or the reviewed buffer.

The latest review replaces the previous AI Proofread
results for that buffer.
Starting another review therefore replaces the corrections
available for application.

Each validated chunk is appended to the current list.
Valid findings are published before any rewrite retry starts.
Retries do not delay findings that were already accepted, and
the next chunk starts only after retries finish.
Findings already removed by apply or ignore are not restored
as later chunks arrive.
The quickfix title remains `AI Proofread`.

The quickfix context reports `complete`, `chunks_done`,
`chunks_total`, `review_id`, `rejected`, `failed_chunks` and
`unreviewable_sections`.
`chunks_done` counts processed chunks and reaches
`chunks_total` when the review finishes.
The `rejected` count includes rejected rewrite retries.
The `complete` flag is false while any chunk is outstanding.
A review that finishes with a failed or unreviewable chunk
also leaves it false.

With `quickfix.auto_open = true`, the quickfix window opens
on the first published finding at the configured height.
The source window and cursor are restored afterwards, so
reviewing does not steal focus.

Pressing Enter on an AI Proofread quickfix entry moves the
source window to that location but leaves focus in quickfix.
Set `quickfix.keep_focus_on_select = false` to use Neovim's
normal focus-changing behaviour instead.

Review never changes the buffer by itself.
Corrections are applied only after one of the explicit
application commands.

Individual application verifies that the source still
matches the reviewed text.
Bulk application preflights every correction, rejects stale
or overlapping ranges, and applies all corrections as one
undoable change.

After an individual correction succeeds, its quickfix entry
is removed and the next outstanding recommendation becomes
current.
Ignoring a correction also removes its entry, advances to
the next recommendation and excludes it from subsequent
bulk application.
After bulk application succeeds, all applied entries are
removed and the quickfix list is empty.
Failed or stale corrections remain in the list.

Apply and ignore also work while a review is still active.
Applying shifts the source ranges of outstanding chunks and
refreshes the positions of published findings.
The review then continues with later chunks.
Ignoring leaves the buffer unchanged, so the review simply
continues.

Any other buffer change makes the review stale.
The plugin then stops the outstanding request and clears the
published entries.
`:AIProofreadCancel` does the same without reporting an error.

If text covered by a recommendation has changed since the
review, that recommendation is not applied.
If any bulk correction is stale or overlaps another
correction, the entire bulk operation is cancelled without
changing the buffer.

After bulk application, one `u` restores the buffer to its
state before the fixes were applied.
Individually applied corrections use Neovim's normal undo
history.
Undo does not restore removed quickfix entries; run
`:AIProofread` again to produce a new review.

Quickfix entries contain source-verified start and end byte
positions. All corrections use warning severity.

If one chunk fails or exceeds the hard limit, findings from
successful chunks remain available.
The quickfix context records the `failed_chunks` and
`unreviewable_sections` counts and leaves `complete` false.

----

== Model Preloading

Set `ollama.preload = true` to begin loading the configured
model asynchronously when `setup()` runs during Neovim
startup.
Startup is not blocked while Ollama loads the model.

By default, preload and review requests omit `keep_alive`,
so Ollama uses its configured `OLLAMA_KEEP_ALIVE` value.
Set `ollama.keep_alive`, for example to `"1h"`, to override
that value for AI Proofread preload and review requests.

Preloading reduces the delay before the first review but
keeps the model resident according to the effective
keep-alive duration and therefore continues to use memory.
These settings apply only to the Ollama backend; the native
`fm` model is managed by macOS.

Preload is best-effort. A failure is reported at debug level
and never blocks startup or a later review.
Set `ollama.preload_timeout_ms` to bound the attempt; the
default is 120000.

Ollama may hold several models at once when memory allows.
By default it permits three models per GPU and queues
requests until memory is available, so a preload can wait
behind another model that is still loading.

== Troubleshooting

Run `:AIProofreadHealth` before reviewing. The message reports
the selected backend and, for Ollama, the models currently held
in memory.

The quickfix title is always `AI Proofread`.
If `context.complete` is false after the final chunk, inspect
`context.failed_chunks` and `context.unreviewable_sections`.
Findings from successful chunks remain available.

A preload request can time out while another model is loading
or while the GPU is saturated. Preload failures are harmless
and appear only at debug level.
Increase `ollama.preload_timeout_ms` if the first load of a
large model is consistently slower than the default.

Ollama unloads idle models and queues new requests when a model
does not fit in memory. Check the effective server settings:

[source,bash]
----
ps eww -p "$(pgrep -f 'ollama serve' | head -1)" \
  | tr ' ' '\n' | grep '^OLLAMA_'
ollama ps
----

`ollama stop` cannot interrupt an active generation.
If a runner remains in `Stopping...`, restart the service only
once your other work is idle.

== Privacy

Reviewed buffer contents are sent only to the native `fm`
process or the configured Ollama endpoint. The default
Ollama endpoint is local loopback. No cloud fallback is
implemented.
